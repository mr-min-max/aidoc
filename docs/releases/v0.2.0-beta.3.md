## Access paths

An eligible ChatGPT subscription authenticates the official local Codex host;
it does not become an OpenAI API key and AiDoc receives no ChatGPT OAuth token.
Claude Desktop and Claude Code authenticate their own host sessions; AiDoc
receives no Claude subscription token. Consumer subscriptions and API billing
are separate.

Direct AiDoc provider mode supports exactly `openai`, `anthropic`, `deepseek`,
`qwen`, `openai-compatible`, and `ollama`. Remote credential variables are
`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `DEEPSEEK_API_KEY`,
`DASHSCOPE_API_KEY`, and `AIDOC_COMPAT_API_KEY`. Ollama is local and requires
an explicit model. Direct provider mode never silently falls back. Qwen custom
AiDoc calls are PAYG Model Studio API use, not a consumer-subscription bridge.

## Boundary and limitations

AiDoc Trust Gate inspects AiDoc's prepared input and validated output.
Configured `strict` blocks findings; configured `warn` or `redact` redacts
detected sensitive values before host generation or return. An `allowed` result
means no findings were detected. Trust Gate does not control a host's context
window, model, sandbox, isolation, or permission system. The host's normal
permissions remain in force. The MCP prepare/validate workflow never writes
the repository, and validation failures are fail-closed: the host stops or
prepares again rather than bypassing the digest or target checks.
