# OIDC-only beta.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `@mr-min-max/aidoc-gen@0.2.0-beta.5` through npm Trusted
Publishing with no reusable GitHub npm credential, then retire traditional
token publishing.

**Architecture:** Keep the existing verify → pack once → checksum → exact
artifact smoke → publish → GitHub prerelease pipeline. Remove the only token
fallback, represent beta.5 as an unpublished candidate while beta.4 remains
the truthful public release, and promote public state only after the registry
and release assets prove success.

**Tech Stack:** GitHub Actions, npm Trusted Publishing/OIDC, Node.js 22/24,
TypeScript, Jest, Node test runner, Markdown.

## Global Constraints

- Work only in the isolated `codex/oidc-beta5` worktree, based on
  `origin/main` commit
  `5ce1e1475f599fbe18e172d4bdc216104a499e74`.
- Use `mr-min-max <254284659+mr-min-max@users.noreply.github.com>` for every
  new commit identity.
- Never expose, print, store, or request the npm token value.
- No product, provider, MCP, parser, CLI, dependency, or public-schema change.
- Preserve Node 22/24 verification, one packed artifact, checksum validation,
  exact tarball smokes, `--ignore-scripts`, `--access public`, `--tag beta`,
  provenance, and post-publish GitHub prerelease ordering.
- A release tag is created only after the candidate is merged to protected
  `main`, the exact commit passes every gate, and the registry reports beta.5
  unpublished.
- `latest` is observed and documented, not removed or moved during this beta
  migration.
