## Reading the table

- Stale docs means a section mentions a changed public symbol and was not modified in the comparison.
- Unmapped symbols changed but are not mentioned in any Markdown under the repository root or docs/.
- Rows with 0 public API changes are kept; see the notes for whether zero means checked-and-clean or not-analyzed.
- `unsupported` is the supplemental count reported by the published plan command; bounded details are recorded in the saved evidence and summarized below.

## Notes per repository

sindresorhus/ky: PR #874 (Improve `Retry-After` handling). The two reported symbols are exported from `source/core/retry-timing.ts` but are not re-exported by the package entry `source/index.ts` at the merge commit. They are internal helpers; `0.3.0-beta.1` counts every export in a changed file as public. The next release scopes the count to symbols reachable from the package entry.

expressjs/express: PR #7366 (feat: allow conditional revalidation for QUERY requests). `lib/request.js` uses CommonJS (`module.exports`, `defineGetter`). `0.3.0-beta.1` cannot enumerate CommonJS exports, so the zero is "not analyzed", not "checked and clean". The next release reports such files explicitly.

pallets/click: PR #3764 (Fix error reporting on Windows when an error is raised in the pager). The change is in `src/click/_termui_impl.py`, a private module by Python convention. Zero public changes is the correct result.

psf/requests: PR #7505 (Add hasattr checks for remaining protocol isinstance checks). `has_read` is defined in `src/requests/_types.py`, whose module docstring states it is not part of the public API; it is absent from `requests/__init__.py` and `docs/api.rst`. `0.3.0-beta.1` reports it as public because it applies the underscore rule to names only, not to module paths. The next release treats `_module.py` as private.
